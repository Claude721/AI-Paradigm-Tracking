## 接口降级原则

- arXiv、HF、OpenAlex、OpenReview 中任一发现源失败，不影响其他源。
- Semantic Scholar、GitHub、HN 任一增强源失败，保留原始论文候选并在报告中暴露证据不足。
- OpenAlex 未配置 Key 时明确跳过，不会使用无效请求。
- 邮件失败不影响数据库与本地报告。
- Hugging Face Daily Papers 是未版本化接口，只作为辅助信号。

## 已验证的本地行为

- 新机制/范式外延硬门槛可以拒绝狭窄增量优化。
- 单篇低声量但新颖、扎实、外延足够的论文仍可通过，不依赖点赞门槛。
- 两篇机制和关键词高度相似的论文会聚合为同一范式。
- 同一范式、同一证据签名不会跨周重复；新证据会标为“进展更新”。
- 报告只展示已验证公开专业页面，不会生成猜测邮箱。
- 每周五时区触发、Markdown 邮件附件均通过本地模拟。

## 仍需处理的生产前事项

1. 申请并填写 OpenAlex 免费 Key。
2. 建议申请 Semantic Scholar API Key，避免作者/引用增强被限流。
3. 填入经过浏览器验证的官方研究博客 RSS/Atom 地址。
4. 核对当年 OpenReview venue id；默认值可能随会议流程变化。
5. 配置 SMTP 授权码和收件人后，再做一次只发给自己的测试邮件。
6. 根目录 `.env` 存在真实凭据的可能性；已新增 `.gitignore`，但仍建议轮换曾经暴露或共享过的 Token。

## 旧版遗留风险

`PIPELINE_MODE=legacy` 仍保留原项目型流水线，但不是当前默认路径。旧版微信解析、子项目脚本和项目增量状态存在既有问题，不影响新版范式雷达；若未来重新启用 legacy，应单独做一次修复与接口联调。

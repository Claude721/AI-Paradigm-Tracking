# 可运行心智模型写作法

## 1. 方法从哪里来

本方法不是通用科普模板，而是从本地 LLMWiki 的真实学习过程反推出来的。分析范围包括：

- `raw/conversations/` 中 38 份长对话；
- 由对话整理出的 8 个学习范式；
- 20 个高价值下一问候选；
- 248 个可由导出分隔符明确识别的后续提问标题。

关键词统计只用来检查模式是否反复出现，不代表严格的语言学标注。重叠计数中，涉及训练/推理/输入输出等信息流的问题最多；边界与假设测试、loss/reward/梯度等学习信号、具体数据结构或最小实例、复述校准也反复出现。真正稳定的共同点不是某种句式，而是：**只有当解释能被放进一个可运行、可反驳的内部系统时，理解才会闭合。**

LLMWiki 原始内容保持只读。本项目只迁移跨主题稳定的认知方法，不复制个人对话全文，也不把某次模型回答当作事实来源。

## 2. 核心判断

普通技术摘要回答“作者做了什么”；高分辨率心智模型还必须回答：

1. 旧系统在哪个接口上不闭合，新方法究竟改变了哪个底层变量；
2. 系统中真实存在什么对象，它们在数据、参数、状态和阶段上分别是什么；
3. 训练时，数据、目标与梯度/反馈如何迫使目标能力出现；
4. 推理或行动时，信息如何逐步变成输出，状态又如何进入下一轮；
5. 用一个最小实例能否把上述过程完整跑通；
6. 移除关键设计、换回旧方法或把条件推到边界时，哪一步会失效。

这六个问题组成“可运行心智模型”，但不是报告的六个固定栏目。研究员应根据技术类型选择真正能打通理解的部分，总编辑再把它们写成自然叙事。

## 3. 对话中反复出现的认知动作

### 先给新知识一个坐标

面对技术报告，先画预训练、Mid-Training、后训练的阶段图；面对密集的 Agent 技术，先按记忆、规划、工具等问题拆路线。全景不是摘要，而是让后续每个细节知道自己位于哪里。

### 从表面矛盾制造解释压力

高价值追问往往来自“形式相似但结果不同”：

- CPT 与 SFT 都可能使用交叉熵，为什么学习效果不同；
- 模型参数静态，为什么下一轮却能拥有不同记忆；
- reward 在序列级，为什么更新仍可落到 token；
- action 是现实动作，为什么能进入张量并计算损失。

这种矛盾能迫使解释从名词定义下钻到真正的变化变量。

### 把术语还原成真实对象

当解释仍然抽象时，最有效的问题是“它在内存里究竟是什么”。图片是 RGB 数组，音频是采样点序列，Mesh 是顶点与面索引，3DGS 是一组高斯参数，机器人 action chunk 是由控制接口定义的连续物理量。对象没有落地，后面的模块关系通常只是熟悉感，不是理解。

### 分开运行训练与推理

同一个模块在训练、推理和部署阶段可能承担不同职责。心智模型需要分别追踪：

- 训练数据从哪里来；
- target、loss 或 reward 在哪里产生；
- 哪些参数开放、哪些对象冻结；
- 梯度或反馈如何穿过接口；
- 推理时输入怎样变成输出或动作；
- 动作执行后怎样重新观测并闭环。

只说“端到端联合训练”或“模型据此生成”都没有闭合因果链。

### 用最小实例跑通信息流

最小实例的价值不是通俗，而是暴露接口：

- 用 7 自由度机械臂抓杯子追踪观测、action tensor、动作生成和控制执行；
- 用三个顶点解释 Mesh 在内存与渲染器中的形态；
- 用 `A=-1, r=0.6` 检查 PPO clip 的真实分段行为；
- 用一段波形追踪 codec token 到 TTS 输出。

实例应尽量小到能逐步演算。自行构造的数字只能解释机制，不能冒充论文结果。

### 通过反例与复述完成校准

把固定状态推到无限上下文，能看出线性成本不等于无限容量；移除 Joint RL，能看出 Zero-Vision SFT 没有视觉坐标校验；用自己的语言复述整条流水线，则会暴露遗漏变量、阶段断裂和同词混淆。最终解释应预先完成这种校准，而不是等读者再追问。

## 4. 不同技术应选择不同的下钻路径

这套方法不是万能文章大纲。研究员应按技术的主要创新位置路由：

- **架构或表示创新**：优先解释对象形态、shape/容量、信息流与推理代价。
- **训练或学习范式创新**：优先解释数据分布、监督粒度、目标函数、梯度归因与投机空间。
- **Agent、机器人或系统创新**：优先解释状态归属、读写接口、行动闭环、时序与失败恢复。
- **数据或评测创新**：优先解释样本怎样产生、标签代表什么、指标与真实成功单位是否一致、是否存在泄漏。
- **正式 Technical Report**：先给全局 pipeline，再只下钻真正改变能力边界的接缝；不要把每个工程细节拆成独立范式。

## 5. 最终报告如何使用

深挖 Agent 会为每条候选生成内部 `mental_model`：

- `anchor_and_tension`
- `system_objects`
- `training_flow`
- `inference_flow`
- `learning_signal`
- `minimal_example`
- `counterfactual_and_boundary`
- `unresolved_interfaces`

这些字段是写作前的检查面，不是可直接交付的正文。总编辑必须重新组织语言：

- 从真正的矛盾或旧瓶颈进入；
- 在必要处引入术语，并立即说明它对应的真实对象和职责；
- 把训练与运行的因果链讲清；
- 用一个最小实例或反事实让机制可演绎；
- 把未披露接口明确保留为未知；
- 最后从被解除的瓶颈推导能力和应用价值。

读完后，读者应当能在不看论文原文的情况下，用自己的话把算法从输入运行到输出，并指出它为什么有效、代价是什么、在哪些条件下会失效。

## 6. 需要避免的写法

- 模块名、论文名和 benchmark 的连续堆叠；
- 用汽车、图书馆等类比替代真实计算对象；
- 把训练过程和推理过程混在一句“端到端”里；
- 只说“引入 X 提升 Y”，不解释学习信号如何产生变化；
- 用作者的宏大 background 覆盖实际 intervention 的尺度；
- 把 `mental_model` 字段逐项做成报告小标题；
- 论文没有披露关键接口时，根据行业惯例替作者补齐。

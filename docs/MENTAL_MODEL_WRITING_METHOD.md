# 快速心智模型与方向势能写作

## 当前周报契约

2026-11-02起以用户提供的 [paper-mental-model](../skills/paper-mental-model/SKILL.md) 为主要解释方法：一个具体失败情境、关键洞察、1–3项必要改变及因果桥，再给关键证据和边界。原件、调用模板与教学案例保留在技能目录；周报运行时只加载[精简适配](../skills/paper-mental-model/references/radar-brief.md)，组合旧技能的观察坐标、纠偏与内部脚手架节，不重复注入整套精读/对话模式。

先选研究对象，再建立完整心智模型；不是研究后按热度删选。研究前使用关注/投入、交叉方向信号或可定位收益对照，缺信号先观察，后续可召回；规则见[研究前选材](FREE_DIRECTION_SOURCES.md#研究前选材)。短正文与深研究分开。通常每条280–450中文字，早期机制200–320字，复杂机制约600字；其中势能约60–120字。安全长度闸门180–900字不是目标篇幅。先让读者复述“原来怎样→关键对象换成什么→为什么有用”，只补一个决定理解的接口；例子与反事实可选其一。默认省略公式、工程参数、排行榜、冗长履历及重复总结。内部心智模型、完整Rubric和原文事实核验仍保留。

以[方向势能技能](../skills/direction-momentum/SKILL.md) 解释谁在用行动下注：分享与真实互动、第三方分析/复现/适配/使用，以及有明确来源的人才和资本行动。势能不是技术是否成立的替身。程序将报告按“已有外部行动—已有可核验传播—早期机制”排列，保留所有可发表结果；第一组可能仅有一次分析或负面测试，不能自动叫成热潮。

这套方法参考“AI行业受力分析”项目中《整理10月扩散与判别模型进展》的最终审阅报告：从代表性增量切入；缺少训练报告时核查已交付产品行为而不反推配方；论文、产品、PR、release、实际使用、融资分别解释；相反评测检查条件，不按来源数量投票。仅采用方法，没有把专题原文、聊天、数据表或固定案例复制为每周seed。

方向增长需要时间序列，不能由本期选中几条论文推出。论文提交增加须固定口径、去重成员和可比窗口；人才入场须既往工作与当前行动配对；融资不等于新公司成立，也不等于客户采用。V0已补充[免费渠道](FREE_DIRECTION_SOURCES.md)：媒体融资报道、选定雇主招聘意向及固定题名队列；它们仍不是全市场资本、人力和领域普查，缺失维度保持未知，不在正文反复罗列免责声明。

### 表达示例（教学示意，不是本期研究结论）

旧方法对每个候选答案分别读一遍同一份长材料，重复成本随问题数增加。新方法先把共享材料算成可复用表示，再让每个问题分支读取；关键变化是共享输入计算，不是把多个问题的判断强行合并。若额外思考占大头，节省共享读入并不能等比例缩短完整请求。应分别核查只读出和含思考两种口径，不用局部加速替代端到端收益。

**讨论势能判断：** 若当前只有发布方的实现和自测，就归入早期信号。真正值得升级判断的是外部引擎开始适配、开发者提交可复核运行记录，或业务方公开实际使用；一次普通转发可说明被看见，不能替代这些行动。

以下保留旧方法的研究解释，供内部下钻与人工精读使用，不是周报篇幅要求。

## 1. 方法从哪里来

这套方法最初从本地 LLMWiki 的真实学习对话中反推：高价值追问反复集中在训练/推理信息流、loss 或 reward、真实对象、最小实例、反事实和未闭合接口。CIDiffuser 的阅读案例又补上了一个更重要的纠偏：**把这些维度列全仍不等于建立心智模型。真正有效的过程，是先选一个观察坐标建立低分辨率运行图，再沿这张图自然暴露的理解缺口逐层下钻。**

因此，高分辨率不等于篇幅长、公式多或模块齐全。它意味着读者脑中始终是同一个模型，只是对象、接口和因果关系越来越清楚。

可执行规范位于 [`skills/technical-mental-model/SKILL.md`](../skills/technical-mental-model/SKILL.md)。本页解释它为何这样设计。

## 2. 先选观察坐标，而不是跟着论文目录走

面对一项工作，先问“站在哪条熟悉流程上最容易看清它改了什么”。可能是模型的输入输出链、训练的目标与梯度链、Agent 的状态行动闭环、表示变换、系统资源瓶颈，或数据生产到评测结论的过程。

一篇论文可以同时涉及 Encoder、SCM、Loss 和 Decoder，但正文只能有一个主导坐标。其他模块只有在闭合主坐标的接口时才值得展开。这样能避免每个地方平均用力，也能让技术细节获得明确位置。

## 3. 用二到四句建立低分辨率运行图

第一版模型只回答三件事：

1. 旧系统怎样运行，卡在哪个接口；
2. 新方法在什么阶段改变了哪个真实对象、约束或信号；
3. 变化如何向下游传播，最终改变什么能力。

这几句话是后文的骨架，不是摘要。它必须足够具体，能够被原文证实或推翻。若只能写成“引入某模块提升了性能”，说明还没有获得可运行模型。

## 4. 从模糊动词中长出下一层问题

重读低分辨率模型，找出“编码、学习、融合、对齐、注入、更新、因此”等承担过多因果责任的词。只保留一旦答错就会改变整体理解的问题，例如：

- 改变的是条件表示，还是噪声动力学；
- 变化发生在训练参数，还是运行时状态；
- 因果图来自结构先验、监督代理，还是无监督发现；
- 一个表示通过何种接口进入后续计算；
- 哪个 loss、reward 或数据结构真正迫使目标能力出现。

按依赖顺序解决二到五个问题。每得到一个答案，都要回写并修正原来的运行图。不能把新细节变成另一条平行的论文摘要。

## 5. 把理解区分为事实、压缩、推断与未知

一个解释可以非常顺畅，却在关键接口上是错的。内部研究档案因此需要区分：

- `source_fact`：来源直接支持；
- `interpretive_compression`：忠于事实的概括；
- `inference`：合理推断，但来源未直接声明；
- `unknown`：材料无法闭合。

读者或分析者自己的复述先作为待验证假说。若原文显示它混淆了对象或阶段，必须重写低分辨率模型，而不是为了叙事连续保留错误。

## 6. 用最小实例和反事实闭合模型

选择一个最小实例，沿主观察坐标从输入运行到输出。实例的目的不是通俗，而是暴露真实接口。随后拿掉核心 intervention、固定其他变量只改变目标变量，或把条件推到分布外与更大规模，检查具体在哪一步失效。

真正有意义的局限会从这里自然出现：属性先验不完备、代理目标不可识别、条件注入被忽略、状态不能跨轮保存、成本随时程失控等。它们不是通用“局限性”列表。

## 7. CIDiffuser 案例提供的校准

以条件扩散流程为坐标是正确方向，但“因果矩阵构造 noise map，扩散模型沿因果噪声路径训练”不符合论文原文。论文实际把监督语义表示经因果效应矩阵与 SCM 变换为 `z_causal`，再通过 AdaGN 把它作为条件注入去噪 U-Net；stochastic branch 才负责随机表示与细节。

因此，更准确的低分辨率模型是：**它没有重画扩散噪声路径，而是在去噪器的条件侧放入一个可干预、带图结构约束的语义表示，并把非目标细节留在另一条旁路。** 修改属性时，变化先经过 SCM 传播，再由同类 DDIM 去噪过程实现为像素。

这个修正自然导出更有价值的问题：属性集合是否完备；效应矩阵是现实因果还是监督代理；预设零边会不会限制泛化；分布外属性组合中条件是否仍能压过训练共现。完整校准见 [`cidiffuser-calibration.md`](../skills/technical-mental-model/references/cidiffuser-calibration.md)。

## 8. 在本项目中的落地

深挖 Agent 会生成内部 `mental_model`，包括主观察坐标、低分辨率模型、决定性 intervention、分辨率递进节点、训练与运行因果链、最小演绎、纠偏、反事实与未知接口。代码会拒绝只有模块清单、没有观察坐标或递进节点的降级结果并触发重试。

路线作者拿到的不是待逐项输出的字段，而是同一张逐步变清晰的运行图。内部可以多层下钻，周报正文只保留真正改变理解的一层；不按论文模块平均分配篇幅，也不把内部字段做成固定标题。原文和人物索引由程序生成，路线起草片段的缓存身份包含当前写作方法与势能代码，避免继续复用旧长稿。

读完后，读者应当能在不看论文原文的情况下，用自己的话说清：

- 站在哪条系统流程上理解这项工作；
- 核心 intervention 在哪里；
- 它怎样改变训练或运行行为；
- 最初直觉中哪些地方被证据修正；
- 哪个未闭合接口最可能推翻当前判断。

# 上下文与流程优化（2026-10-18）

## 保持的边界

这次优化减少重复输入和可选叙事，不通过 Top-K、品牌或削减深挖名单节省 Token。不改 Rubric 题目、选项、权重、技术门槛、原文预算、时效和来源/CAS 保护。单条异常仍独立留档，其他合格结果正常交付；没有合格正文时交付真实运行回执。

没有新增模型、付费调用、Secret/Variable、定时变更或数据上传。MAIN/SUB 保持独立可配置。原始模型判断、人工反馈和历史状态不被改写或删除。

## 实现

1. 抽取、报告索引/机制、综合、人物和单路线写作的固定规则前置，变化的数据后置；保留所有原模板变量、原文与输出契约，有利于兼容提供方的前缀缓存。
2. MAIN 综合保留全部合法创新类型名，先展开公共题和适用类型的完整 Rubric。新类型即使已经返回看似完整的答案，也须在展开真实题目后携带原文复核。新增类型继续变化或结构仍不闭合，只保留该条 pending。首次技术访问与后续结构修复的调度次序不变，跨来源换版不得复用旧修复。
3. 初筛上下文保留版本、类型、离散答案与完整证据说明，不重复传入可重建的总分、权重和问题文本。完整原判断仍保存在候选/私有归档中。摘要只有完整原样出现在当前可见正文节选内才去重；额外摘要事实、稳定 URL、证据编号、指标与折叠账本不删除。
4. v5 的公开身份事实查询仍先执行，避免准入判断与身份查询循环依赖。可选人物模型叙事用于准备发表及可能因人物核验改变准入的边界对象。调度副本的保守估计不写回事实、评分或模型判断。其他路线留存真实未执行状态，并保存技术完成检查点，恢复时不重做已完成研究。已完成的人物判断不被擦除。旧交付版本保留原流程。
5. 用量审计兼容标准 `prompt_tokens_details.cached_tokens` 与兼容 API 的顶层 `prompt_cache_hit_tokens`。异常值/未报告保持未知，命中 Token 仍包含在输入总量，不重复相加或扣减，不据此猜账单。

提示词和研究策略变化会按现有身份规则使相关旧检查点/缓存失效；这不是清库，也不能为了首轮省钱绕过重新核验。平台缓存另由提供方控制，只能根据实际 usage 验证命中。

## 无付费验证

`tests/test_context_efficiency.py` 使用合成材料、模拟模型和临时 SQLite，检查固定前缀/数据完整性、全量题目等价、类型扩展/变更、来源换版、完整判断与人工状态不受调度副本影响、人物完成状态和无重复研究恢复，以及缓存细分未知语义。

最终 Python 3.11.15 完整离线发布门 1,029 项通过（较此前 1,013 项新增 16 项）；失败通知、手动探针导入与 compileall 同时通过。另用 Python 3.12.13 完成项目语法编译；这不等于已在 Python 3.12 执行完整依赖测试。没有真实 API、SMTP、推送或 Actions dispatch。

# 作者身份验证管线

本项目借鉴 [Sherlock](https://github.com/sherlock-project/sherlock) 的小型规则注册表、逐入口结果和正反例测试原则，独立实现职业信息核验；没有引入其代码、依赖或全站扫描。用户名存在只能说明某个账号存在，不能证明它属于论文中的自然人。

## 处理顺序

1. **署名基础层**：从一手原文保存作者、明确贡献标注及逐作者的本工作机构；这一层不等待API或人物模型。
2. **本工作关联**：为新人物档案绑定原点fingerprint、来源版本和原文URL。不借用同名人物或另一条路线的署名。
3. **身份来源**：优先检查原文明确提供的职业主页，再用已配置的OpenAlex及已获得的ORCID补证。OpenAlex需精确规范化题名和唯一作者实体；原始作者ID映射只是查询种子。Semantic Scholar的相近标题可保留引用线索，但人物必须有一致的工作ID或唯一精确题名，并对齐原文姓名及返回作者ID。
4. **有界主页扩展**：页面须有匹配的Person结构或明确人物标题；多人页面只读匹配人物的结构化区段。只跟随该页面同主机、人物路径子树内明确的about/contact/bio/cv链接，深度1、最多2个子页，每次主页检查最多3页。读取进程缓存按完整URL及解析规则版本复用，原始HTML不新增持久化。
5. **职业入口凭据**：个人页明确链接、rel=me、Person.sameAs或已对齐学术档案可以提供职业入口；导航、页脚、仓库/索引路径和只匹配显示名的社交账号不能提供人物事实。页面邮箱仅在可归属的区段内唯一时采用，不生成用户名或邮箱。
6. **可选模型分析**：沿用原有MAIN人物阶段，用对应原文、来源凭据、代表作和公开简介分析研究连续性。没有当前版本绑定时不付费分析无关履历。人物不足、访问失败或超时不撤销技术正文。

姓名比较保留Unicode；不同中文姓名不再因被清成空字符串而相同。学术身份合并要求无冲突的共享稳定ID；新档案中的ID还必须有职业入口凭据，不能凭未核验ID映射继承历史联系人。

## 固定职业链接规则与访问边界

`sources/professional_identity.py`登记GitHub、Hugging Face、Gitee、LinkedIn、ORCID、Google Scholar和X/Twitter的合法个人链接形态，并排除已知组织索引、登录和仓库路径。主机按真实域边界匹配，`github.com.evil.example`不是GitHub。这是链接形态校验，不是账户所有权、账号类型或可达性的独立证明；主页提供职业入口的依据保存在来源凭据中。

不会按姓名拼接任何平台用户名，不新增社交平台搜索，不绕过登录/验证码/反爬，不以浏览器或Cookie作兜底。LinkedIn、X/Twitter、Reddit和小红书不会由通用主页抓取器读取；原有获批平台API配置不变。抓取前及每次重定向前检查公共主机；拒绝私网地址、带凭据或临时签名的URL及HTTPS降级，含跳转在内最多3次HTTP请求、响应解压后上限1 MB。学术API的鉴权不传给ORCID或个人主页。

HTTP 200的登录、挑战和软404页面不是职业资料；被拦截、未找到、错误结构、网络失败、未执行和成功分别记录。查到一个职业入口不代表其他提供方成功。人物适配器的意外程序异常按人物留档，不取消健康同批人物；原点身份种子异常也不让错误处理再次抛出并截断下一原点。确切邮箱或链接被公开提供，不代表本轮访问过其目标页面；查看`contact_provenance`与`identity_observations`区分这两件事。

## 留存与报告

ResearcherProfile新增字段均有默认值，旧JSON可以读取，不需要清库或改数据库列：

| 字段 | 含义 |
|---|---|
| identity_policy_version | 身份规则版本 |
| identity_bindings | 原点、来源版本及原文URL |
| identity_observations | 提供方、状态、固定诊断、URL、观察时间；主页附HTTP状态/解析版本/可用正文摘要哈希 |
| contact_provenance | 每个可展示入口的目标、来源URL、关系及规则版本 |
| profile_leads | 未核验的账号/链接线索，不进入联系方式或人物事实 |
| affiliation_observations | 带来源的机构事实及可用任职日期，不自动称为当前任职 |

OpenAlex最近机构和Semantic Scholar无日期机构只保留为图谱事实。ORCID任职只有明确开始年份、最近一年内更新、未结束且没有其他未结束机构歧义时才作为当前机构；结束任职保存为历史。原文署名机构始终独立展示，不推断任职。

历史档案和人工反馈不删除。只有共享已核验学术ID时，旧联系入口才可随同一人物继承并明确标记`historical_identity`，不是本轮重新读取；历史无日期任职不升级为当前任职。未共享稳定ID的同名档案分开保留；有同名歧义的旧档案必须有自身代表作与当前原文的关联，不能只因署名同名就写入人物索引。人物检查点包含规则/源码签名，不能直接复用旧规则的判断；既有技术检查点依赖身份源代码时也可能重验，不以清库或伪造旧签名规避。

报告及MAIN只使用可展示入口与对应原文，不读取未核验线索。逐入口元数据完整保留，模型投影的检查摘要最多20条、机构事实最多8条，避免历史记录反复撑大上下文。沿用现有审阅留存，不增加第三方归档目的地，也不保存Key、Cookie或完整学术接口响应。

## 配置与验收

无需新增Secret、Variable、依赖、模型阶段或付费搜索。沿用OPENALEX_API_KEY、可选且已获批的Semantic Scholar配置、原有人物配额/阶段时间/样本请求上限。没有OpenAlex Key时仍可尝试原文职业主页与可用署名，不能伪称执行过学术身份查询。

运行`python scripts/offline_checks.py`。新增测试全部使用合成人物、固定时钟、MockTransport和模拟DNS，覆盖中文姓名、同名多原点、多人页面、平台误链、登录200、私网重定向、响应过大、取消、任职日期、部分来源失败、历史联系继承及状态往返。离线通过不代表真实网站/身份接口已上线验收；后续须从正式运行的作者档案和逐入口回执核对，不能只看Workflow绿色或归因人数。

# 技术范式雷达设计

## 第一性原理

目标是：获取足够广的信息 → 核验可解释的机制 → 判断外部承接与趋势 → 交付研究结论。

网站可用性是广度的条件之一，不是最终目标。V0 不要求所有物理入口成功、历史积压清零或全网穷尽普查。技术、真实性与编辑质量仍是硬约束；人物归因为尽力完成的补充。

## 数据与判断

只有原始论文、官方技术发布、原创机制文章和可复核原生实现可以提出机制假说。普通论文通常一个；正式 Technical Report 先建立机制索引，再逐个处理独立 intervention。不同机制不能因品牌或关键词强行合并。

路线按共同 background、问题变化和能力边界聚合。Rubric 回答离散问题并附证据，程序确定性计分；模型不能自报总分来决定趋势。局部 benchmark 优化、营销命名、无机制演示、awesome list 不升级为范式。

Rubric 显式核验 `current_work_intervention`：本工作是否自己提出 AI 技术 intervention 或可执行、可证伪的机制提议。明确复述旧知识/他人工作或设计非 AI 组织制度时，即使其余题得分高也不进入技术路线；未知留观察，不当作技术否定。所有适用题仍须完整回答，漏题是结构待办，不靠默认选项淘汰。纠正非技术误入时允许空心智模型，不虚构训练链；真正技术或贡献未知的候选仍须完整因果脚手架。

Rubric 2026-10-26.2 的技术资格只由技术题计算；发布者、独立验证、传播和多原点承接客观题权重为 0，保持完整辅助记录，不以低声量或未知机构否决。被看见与被验证分账：普通分享、短帖、转发及真实互动可说明传播，无需知名作者或长篇技术分析；作者自身曝光、HF/arXiv 同步收录、索引和 star/fork 不能冒充独立复现。来源、工作和路线绑定仍须核验。

人物只重点核验关键作者。姓名、当前工作、主页/学术 ID 交叉对齐，不猜身份、邮箱、教育或任职。尽量让 MAIN 基于已有代表作、公开简介或当前原文署名分析贡献与连续性，不只依赖 OpenAlex 收录。未找到人物/联系方式、无法可靠归因或补充接口异常均留存真实状态，不阻断合格技术，不降低技术分数；报告只采用已核验人物，其余给出未归因边界。所有材料都可在人物未知时交付技术结论，不限于正式组织报告。

无具名作者、已查未找到、接口异常、未执行和模型辅助归因不足分别记录，不能互相伪装，也不写成技术淘汰或研究未完成。人物模型/辅助阶段失败或超时不回滚技术综合检查点；来源/CAS/存储完整性仍不可放松。实验测量、数据生产或组织制度不能仅因未来可供 AI 使用而当作 AI 技术机制。

V0 的人物身份 HTTP 补充与模型辅助分析安排在全部候选的首次技术访问和剩余时间内的结构修复之后，不在每条候选中插队。技术综合先落盘；人物阶段合计最多占当前对象/批次 60 秒且预留提交时间，时间不足时不启动新的补充调用。v5 先对当前批次核验身份事实，再只为准备发表及人物核验可能改变准入的边界路线生成可选人物叙事；不能先用缺少身份的准入结果否决身份查询。为避免循环筛选，仅在调度副本上保守估计人物诊断可能的贡献，不写回假设值、不据此发表。其余已完成技术判断照常保存完成检查点、署名与未执行记录，不每周重复生成履历；既有人物判断不被擦除，后续满足发表条件时仍可补充。

## 上下文与用量

固定规则、心智模型方法和 JSON 契约位于提示词前缀，变化的材料位于末尾；这有利于提供方的前缀缓存，不保证实际命中。路线综合的 Rubric 保留全部合法类型名，只展开公共题及当前适用类型的完整问题；初筛分类不锁死，模型改判新类型时必须先展开新题、携带原文重新复核，不能凭模型记忆或缺题默认值完成判断。未闭合对象仍 pending，不截断其他候选。

初筛判断进入 MAIN 时保留版本、类型、离散答案和全部证据说明，省略可从 Rubric 重建的题目副本、权重与分数；完整原始判断、输入版本和人工反馈保持不变。只有摘要完整原样出现在当前可见正文节选中才省去摘要的重复副本，不删除额外事实、不缩短正文预算、不改变证据编号或折叠账本。原始输入与最终实际读取的请求仍由私有审阅档案分别留存。

MAIN 综合只返回技术核心：结论、背景/问题/思想、机制及解释、完整心智模型、证据审计、势能、关联编号、适用类型和完整 Rubric。名称、路线名、应用清单、沿革和平台统计不再重写；先前辅助字段保持兼容读取，但不成为事实或准入依据。不提高输出上限，也不以精简为由删除真实实验边界。

Tavily 查询使用真实原点题名及 ID/作者；结果至少绑定完整题名、原文 URL、稳定工作 ID，或全名作者加有辨识度题词。宽泛话题词、模型命名的路线和相关度分数不足以关联。通过关联也只是线索，仍须独立性与实质承接核验。旧缓存中的工作关联未确认索引只进折叠账本、不展开给模型、不被自动排除或判无关；全部原始输入仍参与来源版本/CAS 和私有留存。

缓存命中 Token 是输入 Token 的子集，不是额外用量；审计兼容标准细分字段与兼容服务的顶层缓存字段，并记录缺失次数。不把未报告当成零，不以字符减少或模拟请求证明真实模型质量/账单节省。模型、来源、标准与请求策略变化仍按原签名失效，不能借成本优化复用过期结论。见[验证记录](CONTEXT_FLOW_OPTIMIZATION.md)。

## 本期有界计划

执行模型分为两套独立配置：SUB 用于资格初筛/机制提取，MAIN 用于路线综合/人物轨迹/写作。每套提供方、模型、地址和 Key 都须显式设置，不继承全局、不互相借用。协议按提供方与可选角色 REQUEST_OPTIONS 配置，不按模型名或地址写白名单；策略进入抽取/综合/人物缓存身份。更换兼容 API 不改研究逻辑，仍需技术与事实质量验收。单路线费用保护读取两角色已核验价格数据，不在代码里绑定价格或日历。配置入口见 [清单](CONFIGURATION_CHECKLIST.md)。

1. 并行尝试配置的一手发现通道，每源独立时限、正常限流退避及失败账本，不登录或绕过挑战。
2. HTTP 成功仍须通过条目身份、日期和稳定 URL 契约。原始记录转换、嵌套字段与 JSON 可保存性在聚合/排序前逐条验收；坏记录隔离，健康同伴继续。source_health 分列 raw_results、results、rejected_records；部分坏记录记 warning，整源无可用记录记故障，不能当成功零命中。格式错误不生成技术淘汰。
3. 聚合去重后按来源 → 领域 → 发布组轮转形成最多 4 倍完整研究名额的资格池（默认 192 条）。普通 7 天、高信号 14 天，本期与回补按 3:1 分配；正式报告先展开，同层再按日期排序，不按品牌给资格。已确认非技术材料不消耗 48 个完整研究名额；未知/漏回不作否定，剩余名额可继续访问未知材料。选择不是淘汰，逐源发现/选定与资格池/回答/排除/未知均留审计，冻结批次不重排。
4. 论文、官方文章、原创思想与原生实现均保守资格预筛，不因品牌、seed 或历史 raw 标签跳过；正式报告独立建索引并逐机制接受同版 Rubric。名额前预筛最多 120 秒且不超过剩余研究时间的十分之一，使用现有 SUB 与实际用量保护，不能推断总费用必然下降。成功候选先落盘，再确认原点进度。
5. 先尝试本期原点初筛与去重，再逐一深挖全部合格假说，不删减名单。初筛 observe 不因品牌或传播升级为 deep_dive；当前事件只触发重新核验。历史后台轮询默认 4 条（含 pending），当前事件匹配的旧路线不占这 4 个名额。单对象失败独立留档。
6. 补充传播接口即使全部失败，仍允许以可用一手原文做技术判断；失败/未知回执不变，不能生成“无传播/无承接”的假否定。技术结构、原文和事实门保留；人物与传播不足只保留边界。

第 6 条由同一 `blocking_searches(allow_partial=True)` 贯彻增强、调度、综合、历史刷新和最终交付。严格历史模式仍可显式拒绝未闭合查询。Tavily 次数或月度保护只约束该提供方，保留失败账本，不缩减深挖名单。

已选路线若依赖尚未审阅的新来源版本，显式登记 `origin_dependency_scope` 并补审原点；它与初始 `origin_scope` 分开，完整执行计数包含两者，不借机重新取材或扫描全库。补审成功后才重绑旧假说并重新综合，补审失败仍保留待办。全部**可运行**候选首次访问之后即可为其他对象执行有界结构修复和可选人物补充，不等待不可运行上游；未访问的可运行候选仍优先。付费前重新读取已提交基线；调用开始之后的快照/来源换版冲突继续拒绝，不能刷新期望版本覆盖外来写入。冲突诊断分为对象缺失、状态变化、快照变化和来源变化。

历史召回先匹配本期发现的支持信号与全库工作身份，命中事件的 observe/rejected/pending 均可复核，但不得跳过完整技术判断。无事件对象按最久未检查轮询，pending 转为当前批次独立深挖任务，不再被新周范围静默排除。尚无路线的旧原点通过新事件重新初筛，保存原来源版本；同一事件不会反复重开。新抓取与历史召回重叠时，事件 key 和已见事件集合一起合并，只合并调度元数据，不用旧快照覆盖新正文、日期或来源版本；部分旧事件退出窗口不能使剩余已见事件再次触发初筛。冻结批次续跑仍复用原计划，不因新算法或新事件改写它。

直接 API 的同工作帖子按来源 URL、真实题名/ID和日期核验，生成独立 `diffusion_receipt` v2；它绑定路线、实际匹配且仍支持当前路线的原点身份/版本及帖子 URL/日期，不绑定模型机制措辞，临时正文清除或 MAIN 正常改写后仍保留证据。移除/排除匹配原点、来源换版或帖子身份变化会使凭据失效；无关聚类成员不能借出工作身份。旧 v1 凭据只在原绑定仍有效时升级，失效后不能凭空重建。它只证明工作层面的曝光，不证明每个子机制获承接；机制支持与独立技术承接继续按当前机制严格核验。索引可以优先唤醒复核，但不能生成这个已读回执，也不能充当真实声量。旧路线的 7 天窗口用于传播/采用事件，不限制一手技术年龄；已交付相同签名不重发。

报告索引必须完整逐项校验名称、问题、机制及非空类型枚举，不过滤掉坏兄弟后缩分母。分机制阶段提供全部可选类型的真实题目，允许纠正暂定类型，最终按实际所选类型验证答案。旧索引原始结构保留以维持机制身份；嵌套/对象包装仅无损读取，未知类型重新选择，不降级为 other。缓存完成判断也校验 Rubric 版本、全题和决策，坏缓存只允许被有效修复替代，健康缓存仍防止陈旧覆盖。

报告机制切片失败不能阻止已索引但尚未尝试的兄弟机制。完成判断与失败次数共同证明哪些机制真正访问过；只要还有未访问机制便继续调度、仍按依赖待办记账。所有已知机制均访问而部分失败，原点才可记为已尝试失败。旧错误回执只在同来源版本、失败时间处于精确尝试区间且不存在未访问机制时修正，绝不改成完成或清空 pending。

普通单工作假说可按相同原点身份匹配历史 key，不因语言或名称改变重复创建；多工作聚类、被排除背景材料不提供这个身份捷径，正式报告的独立机制保持分离。现有旧对象不批量删除或伪造合并成功。

综合请求提供各字段的动态合法 index 集合。原点支持、证据排除和实质承接分别判断；官方 implementation 不进入原点支持清单。结构修复收到实际校验原因和合法编号；关联错误重试仍附完整原材料。验证在临时对象上进行，通过后才整体提交，失败输出不得提前修改机制、原点列表或其编号。V0 每条首次综合只发一次请求；解析成功但结构失败、不可读 JSON 和截断草稿（含空正文）都留到全体首次访问后再修复一次，复用首轮证据，不重做外部检索，来源/快照 CAS 冲突仍拒绝。修复上下文同时绑定候选、全部来源版本和 MAIN 请求策略，换源或换模型模式不得使用旧草稿；一次修复失败后不重新排队形成无限循环。

`finish_reason=length` 是输出预算停止，不是技术否定。完整可见 JSON 可进入原有字段、Rubric、身份/基数和证据关联校验，不要求传输原因一定为 stop；不得从损坏的外层包络捞出内层对象、自动补括号、补答案或用隐藏思考代替正文。不可读回答在原有重试中连同原证据作为不可信草稿要求完整替代输出，保持同一 Token 上限。可读 Markdown 先检查句子/代码块收尾，再继续逐路线原文、中文和事实闸门；不可读时同样只作一次请求级修复。内容过滤和工具调用不适用此恢复通道。

审计保留真实 finish_reason 与每次实际用量；`needs_repair` 是该请求需要补全，不是技术 reject，也不是最终剩余待办数。`llm_truncated_accepted_count` 统计截断但当前格式/业务验证可用的请求，不代表路线已经发表。研究健康、路线资格与交付结果仍分别记录。原始可见草稿、补全请求和规范化判断独立留存；不复制隐藏 CoT，不覆盖原模型判断或人工标签。

补全使用普通多轮对话，不启用供应商专用 prefix/beta 或工具协议。当前研究请求不携带 tools；DeepSeek 此模式下不要求回传 `reasoning_content`，见[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。若将来引入工具循环，需另行设计协议，不能直接套用可见文本补全。

arXiv 每查询 100 条；OpenAlex/OpenReview 每查询 2 页；已支持官方目录 2 页，每入口新增详情 6 条。OpenReview 不假设时间排序，不因旧第一页直接停扫；到页限保留偏移和健康结果并记录 page_limit，不能让首个主题耗尽整个发现阶段。审计明确 exhaustive=false，有界取材不是完整覆盖。发现通道数不是独立验证数。

## 两种完成凭据

默认构造器使用 delivery_contract_version=5：本周可发表结果快照与研究计划分别验收。旧 v2/v3/v4 与无版本 outbox 保留冻结契约；未建 outbox 的 v3/v4 活动计划可原地升级，保留窗口、种子、任务与用量。

delivery_scope 保存实际一手通道、当前已知深挖身份、入选路线 key/签名及逐对象版本回执。planned/completed/failed/attempted/unattempted 仍从真实账本推导；未知工作不伪造完成或失败。v5 允许 deep_scope_sealed=false 和未执行对象，来源换版保护不变。

深挖/刷新流程已启动后超时属于该对象的执行失败，不扣住其他路线；尚未启动就没有剩余预算的队尾仍是未尝试。不能把这两种情况统称“预算待办”而重新恢复全局连坐。

- 非空：每条发表路线自身研究成功，并通过技术、时效、原文及中文写作核验；不要求传播强度、知名作者、其他对象完成或最小通道数。传播与验证分账，人物尽力归因。
- 进展更新：本期可没有新论文，但历史路线的刷新完成且新增承接/采用证据在本期窗口内，仍可交付；不要求虚构一个新论文原点才能解锁更新。
- 空：结果为 weekly_receipt，交付本周真实处理范围与运行回执；没有成功判断时不能声称研究证明没有重要技术。
- 预算停止、覆盖不足、依赖/未执行、全部模型或发现失败：记录健康缺口，不否决本周交付。费用未知仍停止后续支出，不自动扩预算。SMTP 或数据库完整性问题仍可使真正交付失败。

发表流程先逐条写作与核验，再冻结成功子集和真实账本；失败只影响对应路线，不改其原始技术判断，不登记已报告签名。合格正文按证据/提示词身份立即缓存，开篇、人物和原文索引确定性组装，无额外总编模型调用。整体研究阶段异常时从已落盘的合格检查点恢复可发表对象；没有则发回执，不回滚健康研究。

research_incomplete、coverage_incomplete 和全局队列仍是真实诊断，不清零造成功；V0 交付资格由范围凭据判断。outbox 写入时从 SQLite 复核来源版本、任务回执、保存候选及签名，且每条入选路线都有自己的已完成深挖/刷新回执，拒绝仅有内存统计的伪凭据。历史失败重开也按当前契约：部分补充平台失败不能在下一次运行把已核验路线重新变成无结论待办。

## 状态与时间

| 状态 | 用途 |
|---|---|
| origin_research_state | 原始来源版本，增强不伪装成来源换版 |
| research_campaigns | 选定计划、固定参考时刻和发现快照 |
| campaign_work / research_attempts | 逐对象版本、完成和异常/预算回执 |
| 候选检查点 / research_stage_cache | 清洗成功子结果，规则/模型/输入换版后失效 |
| provider_credit_* | 实际 UTC 月份额度观察与预留，未知扣费不退款 |
| report_outbox / report_deliveries | 研究与交付解耦，确认后更新已报告签名 |

schema v10 保留 v9 结构，增加 superseded 状态与 V0 范围凭据。V0 reconcile 只纳入当前选定原点及关联路线，不自动加入全库历史任务。

数据库初始化与旧库升级统一在单个 `BEGIN IMMEDIATE` 事务中完成，包含表、列、原点状态迁移及索引；不使用会隐式提交的 executescript 拆开边界。已有正确索引不重建，旧活动计划索引只在定义不同且持有写锁时升级；后续失败整体回滚，不留下半套 schema 或暂时失效的唯一约束。嵌套事务连接按线程隔离，独立连接/进程依靠 SQLite 写锁与原子额度预留协作，不以关闭并发测试绕过竞争。

证据的“读过”和“采用”分开：candidate.evidence 只包含可供当前路线采用的证据；excluded_evidence 保存被模型剔除的原对象。两者并集才是冻结研究输入，版本签名、CAS、来源换版检查都覆盖这个并集。被排除证据不能供应发布者势能、承接、人物或原文索引。新综合可以重新审阅，已完成检查点按原判断复用；无需因正常证据取舍反复报输入换版。

综合模型通过 `mechanism_support_evidence_indices` 显式确认已展开的一手材料对当前机制的支持。程序保存 `mechanism_origin_support`（路线、机制摘要哈希、fingerprint/source_revision），未被确认的可见原点独立保留为排除输入；折叠材料仍保留但不自动加分。同一论文的 arXiv/DOI/镜像入口只计一次；无正面关联回执的历史聚类不自动产生多原点承接。当前模型辅助人物分析状态保存在 `attribution_analysis_status`，原始检索状态不被模型改写。

`execution_summary` 区分本次新增与本期累计。`discovery_resumed=true` 表示取材快照复用，不是本次重新验证全部信源；source_health 的数字属于该快照。全库 pending 是取材/积压诊断，不等于本期计划未尝试。`fresh_research_*` 仅对新发现批次成立，正式交付仍以同版本任务回执与逐路线事实契约判定。

同窗续跑保持窗口、seed、快照和选定材料，不反复重抓失败网站。普通新运行跨过原窗口时归档未交付计划，新一周重新发现；旧失败仍 pending，待投递 outbox 不被吞掉。显式 --resume-research 恢复原计划，未建立 outbox 的 v3 可以升级执行策略，但不更改既有判断或伪造完成。

研究日期与 observation_now 分开，后续观测不倒填原周；首次入库、dateModified 或仅年份不是本期发布。旧路线只在本期新增独立承接、采用或量级变化时更新。

论文首发、修订、平台收录与仓库创建分别保存。多入口合并优先原文日期；arXiv DOI/ID 可桥接同工作，不因不同入口标题产生多份原点。对选定的非 arXiv 原生记录，在来源版本绑定前用公开 landing 补核首发，优先 `[v1]` 历史，其次原文 publication metadata，修订另存；同一 ID 一次请求、失败按对象留档，不能在付费深挖内静默改来源日期。编号年月不能补成当月 1 日，日精度不能冒充精确时刻；与窗口边界重叠时保留日期精度待办，不写成已过期。未知不保证发表，已核验本期传播仍可独立唤醒旧路线。

官方 hydration 卡片按 JSON 数据解析，支持嵌套图片/作者，不执行 JavaScript；日期直接取卡片字段，仍需详情核验。详情中的推荐 post-card 即使使用 `<article>` 也不是正文；目录取链接与详情取正文采用不同用途范围。解析策略进入缓存身份，不以修复布局改写旧模型判断、历史反馈或来源版本保护。

## 报告与交付

每条路线先形成内部技术心智模型，沿同一训练/推理/行动观察坐标递进解释，不输出固定字段清单。程序组合合格路线草稿，确定性生成原文、人物索引及简短取材范围说明，不再追加全篇总编模型调用。

上游模型的机制种子不是事实来源。综合阶段保留每条一手正文最多 16000 字符，长文分布式取样，不再次只截开头；整体 48000 字符证据预算及折叠账本不变。路线作者也获得一手正文，原点证据包上限 22000 字符，用于复核模块、实验条件与结论，而不是只信模型档案。未披露架构不得由行业常识补齐；执行代理、被部署服务模型和实际运行设备分别归因。

所有 HTTP(S) URL 原样来自证据/已核验档案。签名临时 URL、猜测链接、英文长段、内部评分和错误人物归因阻止对应路线发表，不扣住其他合格正文。报告没有阶段性状态或待续研清单。普通运行审计不记录 prompt、模型正文或私有推理；启用私有审阅档案时，实际读入的材料、完整请求及可见回答按[留存指南](RESEARCH_ARCHIVE.md)单独保存，不上传新增公开制品、不保存隐藏 CoT。

报告/SMTP 失败不回滚研究；质量不合格 outbox 隔离并重开相应候选。必需邮件失败不提前登记交付。自动预算续跑默认关闭，额外支出仍受显式开启、健康状态与额度条件约束。

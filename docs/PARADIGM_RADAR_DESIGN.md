# 技术范式雷达设计说明

## 1. 要捕捉的对象

系统的输出对象不是论文、代码仓库或产品，而是一个“可被证据支持、也具备现实承接势能的技术范式假说”。普通论文只是一个机制原点；正式 Technical Report 则可能同时提出若干相互独立的架构、数据或学习机制，抽取层必须分别保留，后续再按共同 background 聚合。

Technical Report 不再一次性生成多套完整档案与 Rubric。报告正文先经过一次紧凑机制索引，只保留真正独立、可被其他团队承接的 intervention，数量由内容决定而非固定配额；随后每个机制单独回答所选类型的 Rubric。这样单项 JSON/证据失败只影响一个机制，其余机制仍可进入深挖；发生部分失败时原始报告保持未完成状态，下轮继续重试。System Card、Model Card 或 Whitepaper 若没有独立技术机制，可以形成“已审阅但无机制”的有效结论，不会被当作系统故障永久重试。

以 World Model 为例，Genie 和 V-JEPA 2 应被描述为谱系里的关键节点：它们分别改变了可利用的数据来源、状态预测方式以及与机器人行动系统对齐的路径。系统要捕捉的是这种能力边界与技术前提的改变，而不是模型名称本身。

发现层不再依赖一组散落在代码里的热门关键词。`taxonomy/frontier_landscape.json` 是版本化的前沿覆盖地图，横向覆盖基础模型、reasoning/软件 Agent、多模态/语音/3D、World/Spatial Model、具身/触觉/自动驾驶、AI4S、数据与学习范式、ML 系统/端侧/硬件、安全对齐和评测治理；纵向再由 Rubric 区分架构、算法、数据、学习、推理、行动闭环、系统与科学发现等 intervention 层。领域术语只是第一条车道，系统还会独立查询重点研究者完整姓名、正式报告/系统卡等文档类型、官方研究索引、HF 策展与人工补录。OpenAlex 明确定位为已知路线的高精度索引：只用标题/主题强命中判断相关分页是否耗尽，不承担未知术语发现。官方索引通过路径结构、JSON-LD、hydration 和详情页 Full Report 链接发现品牌化标题。每次运行在审计中逐领域、逐车道、逐学术索引请求和逐官方入口区分命中、零命中、限流、失败和未执行。因此空报告只能说明在覆盖健康的前提下没有候选通过联合门槛。

## 2. 证据层级

### A. 原点证据

- 原始论文、预印本
- 研究机构/作者的技术博客
- 前沿组织的正式 Technical Report 与高信息量官方发布
- OpenReview 公开投稿

只有这一层可以生成范式假说。

### B. 扎实度证据

- 清晰机制与可核对实验
- 同行评议与作者回复
- 引用网络中的承接关系
- 独立复现和跨任务验证

### C. 扩散证据

- Hugging Face 收藏/讨论
- GitHub 实现、复现和派生工作
- Hacker News 等技术社区讨论
- 后续论文或技术博客的二次解读

扩散层不能把一个弱技术“投票”成新范式，只能提高或降低已有范式假说的可信度。

发布者证据与扩散证据需要联合解释。前沿组织的正式 Technical Report 具有天然的验证与传播势能，进入优先解读；普通论文不能只凭一个知名机构署名直接入选。发布者背景无法核验时，必须看到跨来源实质讨论、独立复现、产品承接或高关注研究者的技术解读，否则留在观察池。

发布者目录采用“召回与背书分离”的四层结构。官方研究索引决定主动抓哪些页面；`established` 组织只登记具名研究团队或实验室，不登记整所大学；`monitored` 组织保证新模型厂商和机器人公司不漏看，但品牌本身不提供准入捷径；重点研究者必须完整姓名精确命中，并由个人主页或学术 ID 交叉核验，结果也只算 `verified`。网页 `og:site_name`、模型品牌或作者自述不能替代 owner 身份。具体目录见 [前沿机构与研究者 Watchlist](FRONTIER_RESEARCH_WATCHLIST.md)。

外部证据在进入评分与写作前必须做相关性审计。arXiv 与 Hugging Face 对同一论文的同步收录只算一个事件；论文日报、awesome list 和关键词聚合仓库不算实现。KOL 或社区信号不仅要记录互动数字，还要保留讨论的技术亮点、争议或用途。作者本人按工作标题发布的帖子只用于对齐身份、简介与公开主页，不算独立二次验证。

社区覆盖分成两层：Tavily 负责发现被公开搜索引擎索引的 X、Reddit、小红书页面和独立技术博客，不参与准入或声量计分；获批的 Reddit OAuth 与可选 X API 才提供官方搜索及互动指标。每个候选保存本轮平台覆盖状态，报告必须区分“没有配置/索引不完整”和“官方搜索后未检出”。社区用户正文只在当轮综合时存在，完成中文提炼与身份核验后清除。

官方仓库与独立验证必须分账。论文项目页直接关联的仓库可以通过真实 star/fork 说明采用与传播势能，但不能同时在“独立实现”和“独立讨论”两栏重复加分。只有非作者团队的复现、后续论文、产品采用或有内容的第三方分析才属于独立承接。

## 3. 版本化 Rubric 决策

技术判断不再要求模型凭整体印象直接输出 0–10 分。最小决策单元是一个带证据的二分或选择题：模型选择 option 并写出材料依据，程序再按 `rubrics/paradigm_rubric.json` 中版本化的 value、weight 与阶段阈值确定性计算。common Rubric 检查问题真实性、机制可复述性、因果链、能力边界、迁移空间和实验控制；architecture、algorithm、learning_paradigm、data、inference、agent_action_loop、embodiment、world_model、scientific_discovery、systems、evaluation 等类型分别加载不同问题。World Model 专项题检查状态动力学和决策接口，AI4S 专项题检查真实科学对象、领域约束、实验验证和发现闭环。发布者、独立复现、二次讨论、研究轨迹与多工作汇聚由程序根据结构化证据自动回答，模型不能自行抬分。

初筛分为“直接深挖、边界复核、观察/拒绝”三种执行语义。普通材料仍须达到初筛 Rubric 的深挖规则；来自正式 Technical Report、重点研究者网络或显式审计补录的高势能原点，如果技术答案完整且落在观察区间，会获得一次深挖复核，避免单次模型边界判断误杀。这个通道只增加研究注意力，不改变最终 Rubric，也不允许弱技术凭名气进入报告。

以下现象会在对应 Rubric 问题取得低值，而不是由一个模糊的“新颖性 5 分”直接硬拒绝：

- 只在单一 benchmark 上小幅提分
- 只减少少量显存、延迟或参数，未改变可实现能力
- 只替换成熟流水线中的一个狭窄组件
- 只换一个垂直数据集，未提出可迁移的数据或学习方法
- 只有营销命名，没有可复述的机制
- 只有高声量，没有实验、评审、复现或合理技术解释
- 发布者身份/轨迹无法核验，同时没有实质二次讨论或承接

效率改进并非一律排除：如果它把原本不可实现的能力变成可实现，例如把推理成本降到能支持持续在线学习，它仍可能改变范式边界。

## 4. 人物追踪边界

系统先识别贡献结构，再决定追踪谁。默认覆盖前三位作者、末位/资深作者和重点名单中的作者；arXiv 官方 HTML 或项目页明确给出共同一作/通讯关系时采用官方标注。大型合作论文不能被写成“名单中最有名者的论文”。研究连续性必须由代表作、年份、机构和主题承接支持。教育、导师、过往任职只在 ORCID、个人主页或本人公开简介明确给出时记录，不能从共同作者关系推测。

联系方式只接受公开专业来源：个人主页、机构主页、ORCID、Semantic Scholar 等学术档案以及作者明确公开的邮箱。不根据姓名和域名猜测邮箱，不收集私人联系方式，不推断创业意愿。

人物增强采用分层核验：高优先级原点在初筛前读取 arXiv HTML 正文与论文项目页；若 HTML 尚未生成或转换失败，则回退读取官方 arXiv PDF。其他通过初筛的候选在深挖阶段补齐作者主页、公开职业邮箱、贡献角色、项目页和代码入口。团队集体署名可以通过精确别名核验发布组织，但不生成个人档案；数百人系统报告没有官方贡献标注时，也不把末位作者机械解释为资深作者。Semantic Scholar 只有显式启用并配置获批 Key 时才提供作者图谱与主页，没有 Key 时绝不匿名请求；OpenAlex 姓名结果必须与当前论文题目对齐；ORCID 补充任职、教育经历、研究者 URL 与公开邮箱；只有已核验的个人主页才会继续检查公开 `mailto:`、LinkedIn 和 GitHub 链接。若配置 X API，还会用工作原始标题搜索发布账号，只有显示名能与论文作者可靠对齐时才补入公开简介。没有联系方式时保留检索记录和最低可确认背景。

## 5. 从候选到研究 Memo

Rubric 只负责上游筛选与审计，不进入最终交付。每一份召回材料都会完成初筛 Rubric；达到深挖规则的候选和高势能边界复核候选都会进入综合，不再固定取前 30 篇或前 16 条路线。综合 Agent 必须调用 `technical-mental-model` 方法：先选择一条能统摄技术的训练、推理、表示或行动流程，用二到四句建立低分辨率运行图，再沿二到五个关键理解缺口递进下钻。每一层都区分来源事实、解释性压缩、推断与未知；只有模块清单、没有观察坐标或递进纠偏的结果会触发重试。

研究总编辑会按共同 background 和能力边界把多篇候选重组成少数技术路线，先写约 500 字的本期总览，再从旧瓶颈、设计哲学、技术落地、路线分歧、客观传播、人物连续性和应用价值连贯展开。技术解释先交付低分辨率抓手，再沿同一运行图提高分辨率，不按论文模块平均用力。心智模型字段只作为写作检查面，不能原样输出为固定栏目。完整方法见 [从低分辨率到高分辨率的技术心智模型写作法](MENTAL_MODEL_WRITING_METHOD.md)。

最终报告不使用总分表、分项评分表、证据 dump 或一篇论文一个固定卡片。证据以 Markdown 链接和客观数字自然嵌入论证；行内粗体只强调关键词与判断。所有解释使用中文转述，英文摘要、英文长句和字段直出会触发一次终审重写；重写仍不合格时停止任务，不生成降级报告、不发邮件。

## 6. 跨周增量

- 证据指纹：优先 DOI / arXiv ID / OpenAlex ID / 稳定 URL
- 内容签名：标题、摘要、作者、机构、学术标识
- 报告签名：稳定路线键 + 证据集合 + 核心机制 + 客观指标量级。Rubric 变化不会单独触发重复发送

新候选会用路线名、共同 background、机制词、谱系和覆盖领域与历史路线图保守匹配，不再只按本周模型临时生成的 canonical key 做精确等号。观察池与已报告路线每周都会用近期 GitHub、Hacker News、X 与聚合支持信号刷新；同一链接的 stars/forks/comments 跨越 1/3/10/25/50/100 等有意义量级时也能触发更新，普通 `+1` 不会制造重复邮件。出现新论文、独立实现、重要讨论或机制描述变化时，允许作为“进展更新”再次交付，但只解释本周新增事实，不重复旧证据。

数据库为空或前沿覆盖地图版本变化时，自动使用 `PARADIGM_BOOTSTRAP_LOOKBACK_DAYS=60` 建立近期路线基线；地图升级不会删除旧数据库，旧证据仍用于跳过已完成分析，只补抓新覆盖面。之后每周使用至少 `PARADIGM_RECALL_OVERLAP_DAYS=30` 的重叠发现窗口。重叠材料由证据指纹过滤，不会重复进入 LLM，却能修复信源失败、索引晚到、发布博客后补完整报告或调度延迟。手动审计某个已知漏项时可用 `PARADIGM_SEED_ARXIV_IDS` 精确回补，arXiv 同时按 `lastUpdatedDate` 捕捉旧论文的新版本。跨代码提交恢复状态由数据库 schema 和覆盖地图版本共同决定，不再因为 commit SHA 变化自动丢掉路线历史；仍可用 `reset_state` 主动清空。

研究数量不能由成本上限决定。发现层按日期窗口自适应翻页，所有发现材料先以 `last_analyzed_at=NULL` 写入可续跑 backlog；机制抽取、外部深挖和历史刷新再按可取消小批次执行。云端软时间预算只决定一次运行处理到哪里：显式补录、正式 Technical Report、官方/重点研究者优先；普通材料在本周新增与旧 backlog 两条队列间公平轮转，各队列内部保持近期优先/FIFO，既不让旧积压挡住金丝雀，也不让积压永久饿死。所有未完成项继续留在 backlog，不能冒充筛选失败。`*_SAFETY_LIMIT` 只有用户显式设置非零值时才作为额外运行熔断；最终研究去留仍只由版本化 Rubric 决定。

每次完整运行同时生成结构化审计，记录信源返回量、arXiv/OpenAlex/OpenReview 查询与请求数、429/失败/熔断/未执行状态、漏斗、材料与路线的可见去留理由、模型阶段与 token 用量。审计不保存 prompt、模型响应正文或模型私有推理；成功时随邮件发送，云端无论成功失败都尽量保存为 Actions artifact。Smoke test 与生产发现严格分离：冒烟使用独立的单请求协议探针，只验证连接、鉴权和最小响应契约，并有逐项总时限；不能导入生产召回器或复用领域车道、详情抓取、cursor/offset 分页器。生产 arXiv 按“显式 seed → 正式报告 → 重点研究者 → 领域地图”使用请求预算；共享限流或网络故障在一次有界重试后熔断，其余车道标为未执行，任何已经成功取得的高优先级材料不会因后续车道失败而丢失。

## 7. 黄金样例与举一反三

`tests/test_frontier_canaries.py` 同时保留 T‑Rex 与 Kimi‑K3 两类全链路金丝雀，但不把论文标题写进生产白名单。T‑Rex 约束行业覆盖、时间窗口、人物贡献、官方仓库与独立讨论分账及跨周路线；Kimi‑K3 约束标题无固定后缀的 Technical Report 识别、arXiv comment 专项召回、团队署名归属、数百作者上下文限长、HTML 404 后的官方 PDF 回退，以及已建立组织系统报告的优先准入。另有 AI4S、World Model、系统/硬件和安全领域的覆盖断言，防止修好一个 case 后其他行业继续静默退化。

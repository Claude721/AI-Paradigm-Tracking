# 技术范式雷达设计说明

## 1. 要捕捉的对象

系统的输出对象不是论文、代码仓库或产品，而是一个“可被证据支持的技术范式假说”。一篇论文只是原点；当同一机制开始出现引用、公开评审、独立实现、复现、讨论或二次解读时，它才逐渐成为趋势。

以 World Model 为例，Genie 和 V-JEPA 2 应被描述为谱系里的关键节点：它们分别改变了可利用的数据来源、状态预测方式以及与机器人行动系统对齐的路径。系统要捕捉的是这种能力边界与技术前提的改变，而不是模型名称本身。

## 2. 证据层级

### A. 原点证据

- 原始论文、预印本
- 研究机构/作者的技术博客
- OpenReview 公开投稿

只有这一层可以生成范式假说。

### B. 扎实度证据

- 清晰机制与可核对实验
- 同行评议与作者回复
- 引用网络中的承接关系
- 独立复现和跨任务验证

### C. 扩散证据

- Hugging Face 收藏/讨论
- GitHub 实现、复现和派生工作
- Hacker News 等技术社区讨论
- 后续论文或技术博客的二次解读

扩散层不能把一个弱技术“投票”成新范式，只能提高或降低已有范式假说的可信度。

## 3. 硬排除规则

以下内容默认不交付：

- 只在单一 benchmark 上小幅提分
- 只减少少量显存、延迟或参数，未改变可实现能力
- 只替换成熟流水线中的一个狭窄组件
- 只换一个垂直数据集，未提出可迁移的数据或学习方法
- 只有营销命名，没有可复述的机制
- 只有高声量，没有实验、评审、复现或合理技术解释

效率改进并非一律排除：如果它把原本不可实现的能力变成可实现，例如把推理成本降到能支持持续在线学习，它仍可能改变范式边界。

## 4. 人物追踪边界

系统优先追踪第一作者，再追踪公开资料中能确认的通讯作者或技术博客作者。研究连续性必须由代表作、年份、机构和主题承接支持。

联系方式只接受公开专业来源：个人主页、机构主页、ORCID、Semantic Scholar 等学术档案以及作者明确公开的邮箱。不根据姓名和域名猜测邮箱，不收集私人联系方式，不推断创业意愿。

## 5. 跨周增量

- 证据指纹：优先 DOI / arXiv ID / OpenAlex ID / 稳定 URL
- 内容签名：标题、摘要、作者、机构、学术标识
- 报告签名：范式键 + 证据集合 + 核心机制 + 分数区间

内容和报告签名均未变化时跳过；出现新论文、独立实现、重要讨论或机制描述变化时，允许作为“进展更新”再次交付，但不重复旧证据。

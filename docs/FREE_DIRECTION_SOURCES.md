# 免费方向信源：来源、验收与边界

核查日期：2026-11-02。目标是补充方向势能，不将融资、招聘或统计热度混成技术验证。所有入口正常HTTP/API访问，无浏览器登录、验证码绕过或个人账号代操作。

上表是一次本机实际访问，不等于GitHub Runner长期稳定性证明。适配器又完成一次独立小样本只读验收，无付费搜索、模型、邮件或研究数据库写入。

本次论文样本窗口为UTC 2026-09-07至10-05（不含），63篇；2026-10-05至11-02（不含），77篇。主题规则与查询由`taxonomy/direction_channels.json`构造；普通主题继承覆盖地图，扩散语言/通用决策评分保留更窄题名口径。每次按该次运行参考日重新取等长28日窗口，不固化本次日期或论文ID，不从修订日、候选数或姓名条目算人才流入。

[Greenhouse官方文档](https://docs.greenhouse.io/job-board)明确公开Job Board GET不要求认证；本项目只读职位，绝不访问申请提交接口。当前注册表只有已对齐的Together AI雇主，不能把它当成整个AI招聘市场。以后可增加已核验的同协议雇主；需要不同协议时先验收，不能靠改URL假装兼容。

## 查到但没有静默启用的渠道

- [36氪官方RSS中心](https://www.36kr.com/rss-center)确实列出Feed地址；本次`/feed`却返回HTML，不是RSS。不能因为HTTP 200就算成功，后续可验收官方其他Feed或公开页面。
- 量子位`/feed`本次连接超时；机器之心旧`/rss`跳到数据服务HTML。保留为待复验，不强行加入默认健康渠道，不绕过护栏。
- 当前插件目录搜索未找到可直接连接的BOSS/猎聘插件；这不等于外部不存在MCP。
- [猎聘官方Agent/CLI授权页](https://www.liepin.com/mcp/auth)已找到，并链接[官方代码仓库](https://github.com/liepin-tech-2026/liepin-cil)。需要用户登录授权；页面写明Token有效期90天、共用60次/分钟限制。尚未验证定时聚合用途许可、只读权限及账户收费条件，不能说已经免费验收。没有安装或索取Token，更未读简历、投递或改资料。未来若选该通道，应只开放职位搜索/查看，并由用户自行在平台授权，凭据不能发到聊天或写入材料。
- 已发现的[BOSS第三方MCP](https://github.com/yahao333/zhipin-mcp)包含浏览器登录、Cookie、投递与聊天，不能直接当成无人值守只读数据API。本次未安装/运行，也不靠模拟用户行为绕过保护。

MCP是一种接入协议，不保证免费、不代表公开API，也不会自动解决授权与定时Runner可用性。已有烯牛连接器的公司分析会消耗积分，本次没有调用；免费增强不依赖它。

## 工程接入

- `PARADIGM_DIRECTION_SIGNALS_ENABLED=true`为默认、已映射GitHub Variable；不要求新Secrets，可设false关闭。
- 默认Feed/岗位每进程至多各读一次，包括失败；arXiv共享限速、最多8个实际匹配主题，每主题最多300条元数据。每次附加阶段45秒，上限或故障只留未知，不扣住其他技术研究。
- 每份背景绑定路线、原点指纹及版本；原点被排除、替换或路线不同就不能借事实和URL。方向背景先用于研究取材，入选后也供路线写作；不作为技术Rubric答案，不计独立承接或本期技术时效。
- 候选JSON保存元数据、实际匹配术语、来源健康、窗口及完整样本ID。新闻/岗位全文不持久化，无简历、候选人、私人信息或新账号Token。写作只展开每主题少量背景，未展开不冒充不存在；完整元数据与模型实际读入的版本保持可关联。
- 报告生成前从保存成员重算数量，错计数、重复ID、换查询和不完整队列不能输出增减；旧投递只能按原as_of说明，不将当前招聘倒填旧任务。

## 研究前选材

`PARADIGM_RESEARCH_FOCUS_ENABLED`默认true，Workflow显式映射，可设false退回旧的技术合格全研究方式。流程是：广泛召回 → 便宜资格与收益预筛 → 有界工作传播查询及免费背景 → 决定研究对象 → 正文补水/完整Rubric/MAIN → 短报告。不是研究完再按热度删选，也不要求先入选才有资格查询关注度。

默认满足下列任一路径即可推进，不要求作者知名，也不要求同时拥有热度与收益：

- 当前工作有已核验外部行动；或本期同工作真实帖子的一项互动指标达到10；或至少2个不同URL、不同可辨识主体的已核验公开帖子。粉丝数、零互动的孤立转发、同一主体重复发布和搜索索引不满足。
- 当前工作相关代码有至少50 stars或10 forks。代码存在或发布者品牌本身不满足，也不当独立复现。
- 同一具体方向至少两类资源/活动线索交叉出现：融资报道、公开招聘需求、完整题名样本增长；论文样本增长要求较前窗至少多3篇且至少20%。当前只有注册表的specialized_topics可仅靠方向交叉证据推进；大模型/智能体等宽领域背景继续展示，但不能给该领域每篇论文通行证。一个宽泛岗位或未闭合计数不能单独推进。这里只说明值得研究这个方向，不声称该具体工作已受到关注。
- 便宜SUB资格预筛在同一次请求中找到摘要明确报告的已执行收益对照，保留基线和量化结果原文短片段；程序逐字核对片段和数字。预测、泛称有实验或模型凭空补的收益不满足。它只是待验证的作者自述，不是已经确认真实生产收益。

这些阈值集中在`taxonomy/direction_channels.json`的`research_selection`，属于可审计取材策略，不进入技术评分。新取材复用现有便宜SUB资格请求；旧待办缺收益缓存时才补有界廉价资格检查。现有HN/GitHub/Tavily/已启用平台的工作查询前移，在廉价资格预筛后的有界取材范围内执行（默认最多48个原点，不对192条廉价预筛池逐条购买搜索），与深挖共享同工作/来源版本/窗口/配置的结果。提供方的次数、月度及未知用量保护不变，不新增模型或搜索厂商；Tavily索引仍不是已核验声量。免费Feed切片、单一雇主和有界arXiv查询限制不变，不保证穷尽。

每批前置工作查询使用120秒预算、单工作至多40秒，沿用增强并发和提供方串行限速；已有网页线索仍有独立的每路线2页/20秒正文读取边界，不能把120秒当成整个研究进程硬超时。未启动记录not_executed，失败维持未知；不能补零或技术reject。进程内失败也复用，避免同一故障连续重复请求；新进程仅重试失败提供方，已保存成功查询的元数据可复用，无需重新购买帖子正文。未取得可恢复检查点就中断的请求不承诺网络exactly-once，费用未知仍受原保护约束。

原点`raw.work_search_checkpoint`只保存来源/窗口/配置绑定的查询元数据与回执，不嵌入社区正文、作者姓名或简介；临时正文只留本进程内供原有综合判断。清理过正文的记录不能充当独立技术分析，Tavily页面可通过已有免费正文读取恢复。跨机制只重绑已核验的同工作曝光，不继承独立技术承接。旧候选在原路线身份下保留自身有效证据，排除材料不参与复查。

无信号或接口未知保存`research_focus.decision=watch`及来源状态、原因和版本，原点仍pending，不标记技术reject或已深挖；选材程序异常另记pending，不冒充观察结论。旧pending在MAIN前复查，刷新在重新综合前复查；有新信号可唤醒，冻结范围不重排。检查点冲突逐对象登记失败，不回写陈旧对象、不阻止其他对象，真实SQLite/文件存储故障仍终止研究。入选且技术初筛通过的全部机制仍逐一尝试，没有深挖Top-K。

## 有界接口复验

```bash
python scripts/check_direction_signals.py --topic diffusion_language
```

此命令会真实访问默认2个免费RSS、1个公开岗位和1条arXiv查询；只打印状态/元数据数量，不调用模型、不发邮件、不写研究数据库。可将topic换成`decision_scoring`或当前覆盖地图领域ID。别把它当全研究运行，失败不应靠充值、无限重试或清库解决。离线测试仍用`python scripts/offline_checks.py`，它关闭联网增强并拒绝网络。

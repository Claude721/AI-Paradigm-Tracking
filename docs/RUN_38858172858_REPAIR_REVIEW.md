## 根因与修复

### 混合证据编号契约

GenIA 等候选同时有论文 index=0 与官方代码 implementation index=1。程序只允许一手原点进入 mechanism_support_evidence_indices；旧提示词没有动态合法集合，静态示例却列 [0,1]，关联失败后的重试也没有实际非法编号反馈。

当前请求逐字段列出合法 index 集合，区分原点支持、证据排除与实质承接；示例数组为空，不能照抄数字。官方 implementation 不是 original_implementation。错误只回显安全的编号/类型，关联修复保留完整原材料。验证在临时对象进行，失败不提前写入新机制、改变证据列表或编号。未知、折叠或二次材料仍不能通过原点支持校验。

现有附件不包含原始响应，所以无法断言每条历史错误的实际非法编号。上述是实际证据形状与代码契约的复现，不是原始模型响应重放。

### 报告切片与失败回执

旧调度将部分报告机制失败标成 dependency_pending，账本又将其当成未尝试；同时遇到失败便停止回排，可能遗漏索引内尚未访问的其他机制。

现在用同来源版本下完成机制和真实失败次数共同核对索引。存在尚未访问的机制时继续调度，仍保持依赖未闭合；已知机制均访问后，部分失败才算原点执行失败。健康兄弟判断和候选先保存，失败不写成技术淘汰。

对真实 state 的临时副本，只有 attempt 259 满足严格修复条件：同来源版本、失败时间位于该次尝试区间且不存在未访问的机制。原点账本由 46 完成/0 失败/2 未尝试变为 46 完成/1 失败/1 未尝试。另一条仍有未访问的分机制，不能改成失败来绕过门禁。19 条深挖和 1 条刷新也继续保持未尝试。

副本 quick_check=ok；修正前后 paradigms 全部原始 payload 字节一致。原始用户制品未修改，未生成正式交付结论。

oss-scanner 同 URL、同来源版本被保留为两条中英文近义候选，旧路线相似度约 0.192。现在普通单工作假说优先按原点身份关联既有 key；同一批普通原点也不会因换名拆成两条。多工作聚类和被排除背景材料不提供该捷径；正式报告不同机制仍分离。

### 全体首次访问优先

生产 v4 每条首次综合只请求一次，先让全部选定候选进入技术流程。解析成功的结构失败在剩余时间内统一修复一次，复用首轮上下文，不重复外部检索，输入变化或完整快照 CAS 冲突时拒绝提交。随后才进行有界人物补充，优先合格路线。未执行、接口失败、未找到保持不同状态。

# V0 实施与验收计划

2026-10-15 按用户澄清更新。全部物理入口/历史积压清零，以及本期全部候选必须成功，都不作为 V0 前置条件。必须全部尝试，但允许单条失败，健康合格路线正常交付。旧设计与事故分析在 Git 历史和 RUN_* 文档中保留。

## 目标

在既定调度和可控成本内，广泛取材、核验趋势、交付完整中文研究结论。可替换模型/API，允许清理无效历史，网站护栏不拖住健康输入。不是无限清偿历史队列，也不保证每周一定有新范式。

## 已实施

1. 默认交付契约 v4：本期计划全部尝试，单条失败保留自身版本回执与 pending，不阻断健康路线；入选路线自身必须成功，未尝试与整体判断故障仍阻断。旧 outbox 保留其原契约。
2. 有界取材与全量深挖：48 原点、全部初筛合格假说、4 历史更新，7/14 天窗口，分页/详情有界，跨发布者/来源轮转。初筛 observe 不因品牌升格，物理入口不要求全绿。
3. 入口/候选故障局部隔离：失败不计零讨论，全部核心判断失败不生成成功空报告。
4. SQLite 范围回执：来源版本、输入基数、候选身份/证据签名与完成事实复核，不能用摘要造成功。
5. 新周计划不被历史锁定；旧未交付计划 superseded，pending 保持真实。
6. Actions MAIN/SUB 各自独立配置提供方、模型、地址、Key，不限定 Qwen；无全局继承/跨角色借用，静态缺项在模型调用前阻断。
7. 独立 V0 状态 epoch 不恢复旧失败队列，旧制品可恢复，费用保护和 outbox 保留。
8. 默认构造器、数据库、非空报告和模拟投递端到端回归；质量/隐私/中文/URL 闸门保留。

## 剩余验收

历史 Python 3.11 / 3.12 各 802 项完整离线门、compileall、3 份 Workflow YAML 和 diff 检查已通过。当前协议与费用验收已改成配置驱动，移除旧模型/地址/日历绑定；最新发布门与实际 Runner 结果以工程体检为准。剩余的是部署后的真实运行验收：

- 部署后检查已有 Variables 的两套角色配置、窗口和关闭平台配置；模型持续结构错误应优先换 API/模型。只有工作流显式映射的 Variables 生效，不用重新填写全部默认参数。
- 获得真实调用/发信授权后做一次有界正式运行：输入 → 判断 → 报告 → SMTP → V0 状态保存。
- 再验证同窗恢复/去重和跨周时间推进，核对真实用量及人工技术质量。
- 依据实际结果调整原点广度、技术筛选、去重与并发；不以深挖 Top-K 缩分母，不自动增加续跑或费用。

## V0 标准

- 有输入且有合格路线时，在单轮预算内产生可追溯中文研究结论。
- 单入口故障不阻断健康取材；单对象故障不回滚或扣住健康判断。执行账本证明全部已尝试，失败不伪装为技术否定。
- 空报告不是模型/抓取失败的伪成功，也不是全网无创新断言。
- 人物、原文、时效、独立承接与每个 URL 契约真实通过。
- 研究失败/报告失败/SMTP 失败分账，确认后才登记交付；重启不丢健康检查点。
- 下个窗口正常推进，历史不持续吞噬本期研究。
- 真实模型/生产结果有证据，不能以测试数量或 Actions 绿色代替验收。

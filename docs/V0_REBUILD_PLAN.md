# V0 实施与验收计划

更新：2026-10-26。当前按 v5 周交付契约执行，旧 v3/v4 的“全量完成/尝试才交付”要求已经失效。历史运行事实保留在 [复盘索引](README.md#历史记录) 中。

## 目标与边界

广泛取材 → 初筛与去重 → 对全部合格候选尽力深挖 → 逐条核验 → 交付合格中文结果。广度、预算和执行完成度是诊断及调度约束，不是扣住健康成果的理由；真实支出保护仍限制后续调用，不自动扩预算。

不要求所有官网成功、历史积压清零或每周必有新范式。没有可发表路线时交付本周运行回执，明确判断/输入缺口，不伪装为“没有重要技术”。人物归因尽力完成，不猜身份或联系方式。

## 已实施的关键路径

1. v5 周交付：单条失败、未执行和全模型故障分别记账；健康已核验路线正常发表。研究健康度、路线资格、实际交付分别记录。
2. 有界取材与长期召回：默认 48 原点、4 条无事件后台轮询；当前事件匹配的旧路线不占轮询名额。观察、旧 pending 和未形成路线的原点都可重访，不绕过技术 Rubric。按来源/领域/发布组分散，逐源选材可审计，冻结计划不重排。
3. 输入卫生：按用途拦住招聘/账户/挑战页，按结构清理页面外壳；明确非研究详情可缓存排除，访问挑战仍待重试。保留旧数据与反馈。
4. 两层独立模型：MAIN/SUB 各自配置 provider/model/base_url/key，可选请求策略进入缓存身份；兼容接口不按模型名硬编码。
5. 研究质量与上下文：所有非正式报告原点均保守预筛，Rubric 核验本工作自身的 AI intervention，不用旧知识或组织制度凑新机制。Tavily 按真实工作身份关联，不纳入泛关键词同名噪声。MAIN 只生成技术核心档案，固定规则前置，去掉完全重复输入，只展开适用 Rubric；不丢原始材料、来源版本或判断。
6. 截断恢复：完整可见 JSON/可读正文仍过原有校验；不可读草稿沿既有有界重试补全。综合先全体首次访问、再一次定向修复，不增 Token 上限或无限重试。
7. 无损检查点与 outbox：先保存下游，再完成上游；原文换版/CAS 防陈旧写入，确认投递后才登记实际发表签名。
8. 私有 JSON：完整实际输入、可见回答、标准、模型判断与人工反馈关联留存；已有人工反馈不被重跑或 merge 覆盖，不训练、不增加模型调用。
9. 离线发布门：无真实网络/密钥/邮箱，覆盖真实编排、临时 SQLite、模拟模型/SMTP、故障恢复和格式契约。

## 下一步验收顺序

1. 提交部署前跑完整离线门并核对源码指纹；当前结果见[工程体检](PROJECT_HEALTH_REPORT.md)。
2. 对当前 MAIN/SUB 及请求策略作当次授权的有界单路线验收。按当日真实价格设费用保护，核对可见正文、reasoning tokens、finish_reason、Rubric 闭合和人工质量。用有明确机制的代表性工作验证正例，用科普/制度与同名无关材料作离线负例，不能以所有对象被拒绝证明质量。历史漏项不是每周固定 seed。Smoke 只验证连接，不代替研究质量。
3. 样本通过后，授权一次完整 7 天运行；核对执行 SHA、来源/输入排除账本、逐阶段真实计数、用量、路线正文与邮件/状态保存。
4. 验证同窗恢复不丢研究、不重复投递，下一周正常取材，不被旧待办永久锁住。
5. 依据真实漏检、误判与用量优化，不为绿色状态降低技术门槛或无限增加预算。

## V0 验收标准

- 有合格路线时交付可追溯中文结论；每条自身通过技术、时效、原文、链接和写作核验。发布者与传播为辅助，普通转发不冒充独立技术验证，弱传播不否决合格技术。
- 单入口/单对象故障不终止健康对象，不把未完成写成技术否定；未执行、失败与完成数可对账。
- 空回执如实说明取材/判断边界，不声称全网无创新或全部研究完成。
- 研究、正式报告 SMTP、辅助数据附件与状态持久化结果分账；正式必需邮件失败不提前登记投递。
- 可恢复、可跨周、能保护人工反馈与真实来源版本。
- 当前模型及生产链路有真实证据；测试数量、低耗时或 Actions 绿色本身不是 V0 认证。

# 论文心智模型阅读 Skill

## 目标与成功标准

帮助读者理解“作者为什么这样设计，以及这个设计究竟改变了什么”，而不是展示读过多少细节。

读完后，用户应能不用论文术语回答：
1. 原方法在哪种具体情境下会出问题？
2. 作者换了什么看问题的方式？
3. 新方法输入什么，经过什么关键变化，输出什么？
4. 为什么这项变化可能解决原问题？
5. 现有证据支持到哪里，什么还没有被证明？

优先级：准确性 > 因果主线 > 可理解性 > 证据完整性 > 细节覆盖率。
快速指输出高信息密度，不指只读摘要。

## 一、阅读契约

- 默认中文回答；保留重要英文术语，第一次出现时用白话解释。
- 将用户视为有技术基础、但尚未建立这篇论文具体模型的研究者。不重复无关基础知识，也不默认其熟悉本论文术语。
- 默认不写正式研究报告，不逐节翻译，不列完所有贡献和消融。
- 公式、工程参数、硬件优化、训练超参数，仅当它们改变核心机制或证据边界时才进入首轮回答。
- 不使用“先列五个难点，再逐一展开”的组织方式。难点只服务于解释核心设计。
- 如用户已有明确理解或刚完成复述，直接在该理解上继续，不重新讲整篇。
- 用户明确指定长度、结构、关注点时，覆盖本 Skill 的默认格式。

## 二、先获得原文，再形成解释

### 最小充分阅读

1. 确认附件/路径/URL对应的题目、版本与可读性；批量任务先建立文件—论文映射。
2. 摘要与引言：定位问题及作者声称的贡献，不把宣传句直接作为结论。
3. 方法正文：读清变量、流程、损失、训练与推理差异。
4. 核心示意图/算法：核对信息在模块间如何流动。
5. 主结果和最关键的机制消融：验证改变是否有效，以及实验是否隔离了原因。
6. 局限、附录：定向查证决定解释是否成立的细节，如样本筛选、真实标签、参数统计、比较口径。

不必逐字读完所有附录，但不得在未核对方法与证据前声称“已完整精读”。如果只有摘要或原文缺失，明确给出可解释范围，不自行补全算法。

### 信息来源纪律

- 用户提供原文时，优先以该版本为依据；外部材料只用于必要背景或用户要求的验证。
- 有文件工具则读文件；有本地终端则使用可用PDF提取工具。提取丢失的公式或图表必须核验，不能凭残缺文本猜测。
- 外部链接按所在运行环境的规则读取。不要因 Skill 中出现工具描述就虚构本地工具能力。
- 引用优先指向方法节、公式号、表号、附录或PDF页码。区分PDF页码与论文印刷页码。
- 本地环境无专有引用标记时，使用如“[原文 §3.1，式(5)]”的定位。绝不复制其他环境中的文件ID，也不编造引用。
- 原文事实、作者解释、自己的推断必须能被区分；无需每句加标签，但关键争议处明确说明。

## 三、内部先完成一张机制卡

这张卡用于组织推理，不要求逐项展示给用户：

- 旧范式：原系统怎么工作？
- 具体失败：哪种情境下，哪条假设失效？
- 关键洞察：作者认为真正应该改变什么？
- 最小干预：去掉所有实现包装后，方法剩下哪1—3个必要改变？
- 数据流：输入 → 中间对象 → 关键操作 → 输出。
- 学习信号：目标从哪里来？谁提供标签？监督谁？
- 训练/推理：训练时知道什么，推理时还能知道什么？
- 因果桥：每个设计如何对应原问题，而非仅与问题同时出现？
- 核心假设：机制成功依赖什么尚未普遍验证的条件？
- 证据：哪一个结果或对照最能支持主张？
- 边界：什么结果不能由该证据推出？

若不能填清输入、监督来源或训练/推理区别，先回原文，禁止用更长的类比掩盖缺口。

## 四、默认输出：先主张，再机制，再证据边界

以下是骨架，不是每篇必须机械套用的目录。

### 1. 一句话定位

“这篇不是在做X，而是把Y从A改成B，试图解决C。”
必要时说明它属于架构、表示学习、训练目标、推断算法、系统实践或混合工作。不要因为包含大量系统内容就否认其算法贡献，也不要把常规工程优化拔高成新范式。

### 2. 原方法为什么不够

只选一个最能解释新设计的具体失败情境。先讲现象，再命名术语。不要先列整个领域的历史和所有瓶颈。

### 3. 作者做了哪一两个关键改变

每个设计按下列顺序解释：
- 原来是什么；
- 现在换成什么；
- 为什么换了之后可能解决前述问题。

需要时用一个短文本图：
旧：A → B → C
新：A → 新的中间对象 → 新操作 → C

不要把“用了某模块”当作完整解释。必须说明该模块增加了哪种信息、依赖、监督或约束。

### 4. 贯穿一个最小例子

优先使用一个例子走完整个机制，而不是每节换一个比喻。示意数字明确标为教学例子。类比之后必须映射回真实变量，并提醒最容易误解之处。

### 5. 证据与判断

通常只选1—3项关键证据：一项主要结果、一项最有鉴别力的对照、必要的一项边界。

先说实验支持什么，再说未证明什么。避免大表格、完整排行榜和无关小数。最后如有必要给一句记忆锚点，不重复全文。

默认单篇约1200—2200个中文字符；机制复杂可适度超出，原理简单则更短。长度不得反过来迫使删去改变结论的限定条件。用户重点追问时，只讲缺失部分。

## 五、核心技巧与强约束

### A. 找“改变对象”，而不只看方法名称

问：它改变了表示单位、条件信息、生成顺序、可用记忆、监督来源、目标函数、采样规则，还是执行成本？
名称中的concept、reasoning、world、reward等词不自动证明对应能力。用实际建模对象解释术语。

### B. 学习信号必须溯源

遇到reward/value/potential/distillation/consistency，检查：
1. 什么对象是输入？
2. 标签或目标值从哪里来？人工、环境、最终结果、参考答案、teacher还是自身预测？
3. 被训练的对象是什么？策略、评估头、adapter还是主干？
4. 哪些样本保留，哪些丢弃？
5. 一次观测与期望目标有什么区别？
6. 是否先后训练，还是联合训练？

特别禁止把“用终局结果训练状态价值”说成“获得了真实逐步奖励”，把成功样本CE说成policy gradient，把同一轨迹标签相同误解为沿途预测必须相同。

### C. 区分看起来相似但不等价的机制

- 隐藏状态历史 ≠ 上一轮输出分布。
- 置信度提升/熵下降 ≠ 正确率提升。
- teacher forcing参考条件轨迹 ≠ 自由生成轨迹。
- 自生成数据 ≠ 必然on-policy；核对是否随当前模型刷新。
- 架构增加信息通道 ≠ 纯Infra缓存优化。
- 可表达某种行为 ≠ 实验已证明出现该行为。
- 直觉上的“距离” ≠ 实际优化的度量。
- 理论理想目标 ≠ 实际可计算的代理目标。

### D. 解释复杂公式的三级阶梯

先讲它约束什么行为，再用例子，最后只有必要时给一个公式。
公式出现时，每个变量都必须对应直观对象。不要从完整推导开始；但如果简化会改变算法性质，保留那条必要关系。
用户问“怎么训”时，给出输入—标签—损失—样本来源的最小闭环，而不是泛泛说“从大量数据学到”。

### E. 控制工程细节

默认省略kernel、异步传输、packing、显存调度、投影维度、学习率等。
以下情况例外：
- 工作本身主要是系统论文；明确其价值在执行效率与部署约束，不虚构算法新意。
- 某执行设计改变方法是否可用或比较是否公平；用一两句交代影响即可。
- 用户明确要复现、部署或系统分析。

### F. 读实验先检查分母

- 加速相对谁：未优化基线、优化DLM还是AR投机解码？
- 是否同精度、同硬件、同batch、同长度、同采样与失败计费？
- TPF/NFE与墙钟时间不能互相代替。
- 参数规模是否只统计生成器，漏掉tokenizer/decoder/teacher？
- token exposure不等于FLOPs，后训练预算不等于总训练预算。
- token重建准确率不等于整段无损率。
- generative perplexity是外部模型对样本的评分，不自动等于模型自身似然或通用能力。
- 单一任务、单一规模、单次对照不自动支持广泛scaling或因果结论。

只有改变解释的口径才呈现，不把所有评测元数据倒给用户。

### G. 对scaling既不吹捧，也不迎合否定

“尚未验证大规模成立”不等于“无法scale”。
区分：已经测试的规模、可解释的潜在瓶颈、仍需实验的假设。保留用户合理怀疑，但不要顺势把猜测说成论文结论。

## 六、对话模式

### 用户复述

1. 简短确认已理解部分。
2. 只指出会影响心智模型的偏差，通常不超过2—3点。
3. 用“你说的X更准确应是Y，因为Z”校准。
4. 回答其真正卡住的问题，不重新讲整篇，不把措辞小误差变成概念考试。

### 用户问某一步怎么工作

只补当前缺口：
- 怎么训练 → 展示训练样本、标签来源、最小损失及预测用途。
- 为什么有效 → 连接设计与原失败情境，指出关键假设。
- 与另一篇区别 → 围绕共享问题，比较改变对象与监督信号。
- 是否新范式 → 区分表示/概率分解/学习目标变化，与实现加速。

### 用户说“太细/没懂”

不要仅缩短原回答。换一个抽象层级：删掉实现，将方法重写为一个问题、一个新中间对象、一个学习闭环。若旧解释过度简化或失真，明确更正。

### 批量论文

1. 先用一张很短的地图说明各篇改变了哪一层对象。
2. 按利于理解的顺序逐篇讲，说明排序理由；如用户指定顺序则遵从。
3. 共享背景只讲一次，但每篇必须有独立机制解释，不能只给总览表。
4. 明确相似点与不等价之处，不为叙事强行归为同一方法。
5. 末尾最多归纳2—3条共同趋势，并区分作者结论与综合判断。
6. 批量过大且无法在一轮可靠处理时，先给完整清单与阅读安排，明确本轮覆盖范围，不假装已精读全部。

## 七、发布前自检

- 能否用两句话说出核心设计，而不用堆方法缩写？
- 是否解释了设计为何对应原问题？
- 输入、输出、目标来源及训练/推理边界是否核对？
- 是否把预测前景、熵下降、并行能力误说成真实逐步奖励、正确性或潜在推理？
- 去掉实现段落后，读者是否仍能理解全部核心机制？若能，应删去实现段落。
- 类比和示意数字是否明确不是实验事实？
- 证据是否真的支持主张，是否漏掉关键比较分母？
- 是否坦诚说明未读到、未验证或无法判断之处？
- 用户能否复述“原来怎样 → 现在怎样 → 为什么可能更好”？

详细质检与教学案例见 references/quality-and-examples.md；只在需要时读取。
